# Основные требования

Эти функции разделены на два уровня. **Core** (основа) даёт законченный, впечатляющий продукт. **Stretch** (расширение) выводит его на следующий уровень. Оставшиеся функции (поиск контента и онбординг, дайджест, настройка раскладки) — это дизайн-задачи, в которых продуктовые решения принимаешь ты; см. `design-challenges.md`.

Core + одна функция, спроектированная самостоятельно, + один дифференциатор — это сильная работа для портфолио.

---

# Core

Эти 12 функций образуют полноценную читалку фидов. Полностью рабочий продукт с аутентификацией, гостевым доступом и отполированным лендингом.

---

## 1. Управление фидами

Пользователи могут добавлять, редактировать и удалять подписки на RSS/Atom-фиды.

**Критерии приёмки:**

- Добавление фида по введённому URL
- Перед сохранением проверяется, что URL указывает на валидный RSS- или Atom-фид
- После успешного добавления отображаются название, описание и фавикон/иконка фида
- Редактирование пользовательского названия фида и назначенной категории
- Удаление фида с подтверждением
- Отображение статуса здоровья фида: активен (последняя загрузка успешна), устарел (не обновлялся 30+ дней), ошибка (последняя загрузка не удалась)
- Отображение времени последней успешной загрузки для каждого фида

---

## 2. Парсинг фидов

Разбор реальных RSS/Atom-фидов со всеми их реальными несоответствиями.

**Критерии приёмки:**

- Парсинг фидов RSS 2.0
- Парсинг фидов Atom 1.0
- Парсинг фидов RSS 1.0 / RDF
- Обработка типичных проблем с кодировками (UTF-8, ISO-8859-1, Windows-1252)
- Нормализация HTML-сущностей в заголовках и описаниях
- Обработка фидов, в которых отсутствуют необязательные поля (нет описания, автора, даты публикации)
- Извлечение и нормализация дат в разных форматах (ISO 8601, RFC 822, RFC 2822, распространённые нестандартные форматы)
- Обработка фидов с полным HTML-контентом и фидов с текстовыми аннотациями
- Корректная обработка некорректного XML (частичный разбор, где возможно; понятная ошибка для полностью сломанных фидов)

---

## 3. Просмотр контента

Просмотр записей фидов в чистом, легко просматриваемом интерфейсе.

**Критерии приёмки:**

- Записи отображаются с заголовком, названием источника, датой публикации и отрывком/описанием
- Рядом с каждой записью показывается фавикон или иконка источника
- По умолчанию записи отсортированы в обратном хронологическом порядке
- Фильтрация по фиду или категории
- Показ количества записей по каждому фиду и каждой категории
- Бесконечная прокрутка или пагинация для больших списков (100+ записей должны работать без потери производительности)
- В смешанной ленте записи из разных источников чётко различимы

---

## 4. Организация по категориям

Фиды раскладываются по категориям, которые задаёт пользователь.

**Критерии приёмки:**

- Создание собственных категорий (например, Frontend, Design, DevOps, AI, Newsletters)
- Назначение фидов в категории (одна категория на фид)
- Просмотр всех записей внутри категории
- Переименование и удаление категорий (при удалении фиды переназначаются или становятся без категории)
- Категории отображаются в боковой панели или навигации со счётчиками непрочитанного
- Категория по умолчанию «Без категории» для фидов, у которых категории нет
- Изменение порядка категорий перетаскиванием или вручную

---

## 5. Отслеживание прочитанного

Учёт того, какие записи пользователь уже видел.

**Критерии приёмки:**

- Запись помечается прочитанной при клике/открытии
- Прочитанные и непрочитанные записи визуально различаются (прозрачность, насыщенность шрифта или индикатор)
- Ручная пометка отдельных записей как прочитанных/непрочитанных
- «Отметить всё прочитанным» для фида
- «Отметить всё прочитанным» для категории
- «Отметить всё прочитанным» глобально
- Состояние прочитанного сохраняется между сессиями
- Счётчик непрочитанного в навигации (по фиду, по категории, общий)

---

## 6. Просмотр статьи

Пользователь может прочитать статью целиком или перейти к ней.

**Критерии приёмки:**

- Клик по записи открывает оригинальную статью в новой вкладке
- Если фид отдаёт полный контент (а не только отрывок), предлагается режим чтения внутри приложения
- Режим чтения аккуратно отображает HTML-контент: заголовки, абзацы, списки, блоки кода, изображения
- Режим чтения убирает из HTML фида рекламу, навигацию и элементы, не относящиеся к контенту
- В режиме чтения показываются метаданные статьи: заголовок, автор, источник, дата публикации
- Из режима чтения есть ссылка на оригинал
- Переход между записями без возврата к списку (следующая/предыдущая)

---

## 7. Адаптивный дизайн

Приложение хорошо работает на разных устройствах.

**Критерии приёмки:**

- Раскладка естественно подстраивается под размер экрана — пусть брейкпоинты диктует контент, а не конкретные значения в пикселях
- На небольших экранах: одна колонка, сворачиваемая навигация, удобные для касания области нажатия
- На больших экранах: используй пространство — подумай, как могут сосуществовать навигация, список и чтение
- Нет горизонтальной прокрутки
- Навигация доступна и удобна на экранах любого размера
- Размеры шрифтов и отступы комфортны для чтения на каждом классе устройств
- Изображения и медиа в контенте фидов адаптивны

---

## 8. Обработка ошибок фидов

Корректная работа в условиях, когда фиды ненадёжны.

**Критерии приёмки:**

- Понятное состояние ошибки для фидов, которые не удалось загрузить (сетевая ошибка, таймаут, 404, 500)
- Временные ошибки отличаются от окончательно мёртвых фидов
- Повторные попытки для упавших фидов с экспоненциальной задержкой
- Время последней успешной загрузки показывается, даже если текущая загрузка не удалась
- Один медленный или сломанный фид не блокирует весь интерфейс
- Пользователь может вручную повторить загрузку упавшего фида
- Панель или индикатор здоровья фидов (сколько фидов в порядке, сколько с ошибками)

---

## 9. Аутентификация пользователей

Безопасный персональный опыт.

**Критерии приёмки:**

- Регистрация по email и паролю
- Вход / выход
- Сброс пароля
- Все данные пользователя (фиды, категории, состояние прочитанного, закладки, настройки) сохраняются за аккаунтом
- Состояние авторизации сохраняется между сессиями браузера
- Защищённые маршруты перенаправляют неавторизованных пользователей на страницу входа
- Гостевой режим позволяет полноценно изучить приложение без аккаунта (см. требования «Попробовать как гость»)

---

## 10. Лендинг

Первое впечатление и точка входа.

**Критерии приёмки:**

- Первый экран (hero) с ясным, убедительным ценностным предложением
- 3–4 ключевые возможности, которые объясняют, чем полезен Frontpage
- Два призыва к действию: «Зарегистрироваться» и «Попробовать как гость» — оба заметные
- Адаптивный дизайн, который хорошо работает от мобильных до десктопа
- Визуальное качество, задающее профессиональный тон всему продукту
- Быстрая загрузка (никаких тяжёлых ресурсов, блокирующих отрисовку)

---

## 11. «Попробовать как гость»

Посетители могут изучить всё приложение, не создавая аккаунт. Это критично для ценности портфолио: когда нанимающий менеджер, коллега или участник сообщества откроет твою ссылку, он не станет регистрироваться. Гостевой режим — то, что позволяет им увидеть твою работу.

**Критерии приёмки:**

- В гостевой режим можно войти одним кликом с лендинга
- Панель заранее наполнена 19 подобранными фидами в 5 категориях (см. файлы в `data/`)
- Гость видит полностью заполненную панель с реальным контентом, разложенным по категориям
- Гость может просматривать, искать и переключать раскладки
- Мягкие приглашения зарегистрироваться, чтобы сохранить данные (без агрессивных ограничений)
- Данные гостя живут в пределах сессии (не сохраняются между визитами, пока он не зарегистрируется)
- Понятное объяснение того, что даёт регистрация (сохранение, свои фиды, синхронизация)

---

## 12. Хранение данных

Все данные пользователя хранятся в настоящей базе данных.

**Критерии приёмки:**

- Используется настоящий сервис баз данных (Supabase, Firebase, Neon, PlanetScale и т. п.)
- Хранятся: подписки на фиды, категории, записи фидов, состояние прочитанного, закладки, настройки пользователя
- Данные авторизованных пользователей сохраняются между сессиями и устройствами
- Эффективные запросы — не загружать все записи, когда показывается одна категория
- Корректная обработка одновременных изменений (несколько вкладок, оптимистичные обновления)

# Stretch

Эти 6 функций выводят продукт на следующий уровень. Они опираются на фундамент Core и рекомендованы разработчикам, которые хотят копнуть глубже.

---

## 13. Закладки / «Сохранить на потом»

Сохранение статей в постоянный список для чтения.

**Критерии приёмки:**

- В закладки можно добавить любую запись из списка или из режима чтения
- Все закладки доступны в отдельном разделе «Сохранённое»
- Закладки удаляются по одной
- Закладки сохраняются между сессиями
- Счётчик закладок в навигации
- Сортировка закладок по дате сохранения или дате публикации
- Поиск по закладкам

---

## 14. Поиск

Поиск контента по всем фидам.

**Критерии приёмки:**

- Полнотекстовый поиск по заголовкам и описаниям записей
- В результатах показываются подходящие записи с подсветкой искомых слов
- Фильтрация результатов по фиду, категории или диапазону дат
- Поиск быстрый (результаты появляются по мере ввода или в пределах 500 мс после отправки)
- Состояние «ничего не найдено» с полезной подсказкой
- История недавних запросов (необязательно, но приятно)

---

## 15. Импорт/экспорт OPML

Поддержка стандартного формата подписок на фиды.

**Критерии приёмки:**

- Импорт фидов из стандартного OPML-файла
- Предпросмотр импорта: список добавляемых фидов с пометкой дубликатов
- Обработка вариаций формата OPML (вложенность outline, разные имена атрибутов для URL)
- Дубликаты (тот же URL уже в подписках) пропускаются или помечаются
- Отчёт о результатах импорта: X фидов добавлено, Y дубликатов пропущено, Z невалидных фидов
- Экспорт текущих подписок в OPML-файл
- В экспорте OPML сохраняется структура категорий
- Успешная обработка приложенного файла `sample-feeds.opml`

---

## 16. Обновление и опрос

Контент остаётся свежим.

**Критерии приёмки:**

- Кнопка ручного «обновить всё» с визуальной обратной связью (состояние загрузки, подтверждение успеха)
- Ручное обновление отдельного фида
- Настраиваемый интервал автообновления (15 мин, 30 мин, 1 час, только вручную)
- Отметка времени «последнее обновление»
- Визуальный индикатор появления новых записей (баннер «5 новых записей» или подобное)
- Фиды, которые не изменились, не загружаются повторно (ETag или Last-Modified там, где они поддерживаются)
- Обновление не блокирует интерфейс — пользователь продолжает просмотр, пока фиды обновляются в фоне

---

## 17. Производительность

Приложение должно ощущаться быстрым и отзывчивым.

**Критерии приёмки:**

- Первичная загрузка ленты занимает меньше 3 секунд
- Плавная прокрутка сотен записей (без рывков)
- Эффективное кэширование, чтобы не загружать повторно неизменившиеся фиды
- Изображения загружаются лениво и не блокируют первую отрисовку
- Результаты поиска появляются в пределах 500 мс
- Время до интерактивности на лендинге меньше 2 секунд
- Нет сдвигов раскладки во время загрузки контента (скелетоны или плейсхолдеры)

---

## 18. Клавиатурная навигация

Полноценная система горячих клавиш, которая делает приложение быстрым и удобным для опытных пользователей.

**Критерии приёмки:**

- `j` / `k` — перемещение между записями в списке
- `o` или `Enter` — открыть выбранную запись
- `s` — сохранить выбранную запись в закладки (если закладки реализованы)
- `m` — переключить прочитано/не прочитано для выбранной записи
- `g`, затем `h` — на главную; `g`, затем `s` — в сохранённое; `g`, затем `f` — к фидам (составные сочетания в стиле vim)
- `/` — фокус на поиск (если поиск реализован)
- `?` — показать оверлей со справкой по горячим клавишам
- Командная палитра (Cmd/Ctrl + K) для быстрых действий: сменить категорию, перейти к фиду, искать, поменять раскладку
- Визуальный индикатор фокуса, показывающий, какая запись сейчас выбрана
- Выбранная запись автоматически прокручивается в область видимости
- Без конфликтов работает вместе с мышью и касаниями — клавиатура и указатель не мешают друг другу

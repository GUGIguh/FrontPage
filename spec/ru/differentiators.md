# Дифференциаторы

Дифференциаторы необязательны, но рекомендованы. Выбери 1–2, если хочешь продвинуть проект дальше и показать более глубокую экспертизу.

Каждый из них демонстрирует конкретную область навыков и заметно меняет пользовательский опыт. Выбирай исходя из своих интересов и навыков, которые хочешь показать.

Опиши в README свой выбор, подход к реализации и то, чему ты научился.

---

## 1. Суммаризация с помощью ИИ

**Область навыков:** интеграция ИИ

Используй ИИ, чтобы помочь пользователям обрабатывать больше контента за меньшее время.

**Что сделать:**

- Генерация кратких пересказов длинных статей (выжимка полного текста в 1–2 абзаца)
- Автоматическая расстановка тегов по темам, когда категории фидов недостаточно конкретны
- Дайджест «Главное за неделю», который суммирует самый заметный контент по всем фидам
- Умные предложения по категоризации: «Похоже, этому фиду место в „Frontend“ — перенести?»
- Необязательно: поиск на естественном языке («статьи о производительности React за прошлую неделю»)

**Чем это впечатляет:** интеграция ИИ — отличие, которое работодатели активно ищут. Сделать её хорошо — значит справиться со стоимостью API, задержками, кэшированием пересказов, аккуратными запасными сценариями и UX, в котором ИИ помогает, а не навязывается.

## 2. Поддержка чтения офлайн

**Область навыков:** производительность / PWA

Кэшируй статьи для доступа офлайн, чтобы пользователи могли читать в дороге.

**Что сделать:**

- Service worker, кэширующий контент фидов для чтения офлайн
- Действие «Сохранить офлайн» для отдельных статей
- Автоматическое кэширование свежих записей (за последние 24 часа или последние 50 записей)
- Индикатор офлайн-режима в интерфейсе
- Очередь действий, совершённых офлайн (отметить прочитанным, добавить в закладки), и синхронизация при возвращении в сеть
- Управление размером кэша (очистка старых записей, учёт объёма хранилища устройства)
- Манифест Progressive Web App (PWA) для установки на главный экран

**Чем это впечатляет:** поддержка офлайн показывает понимание service worker'ов, стратегий кэширования и разрешения конфликтов синхронизации — продвинутых навыков веб-платформы, которые ценятся всё выше по мере того, как веб-приложения конкурируют с нативными.

## 3. Интеграция почтовых рассылок

**Область навыков:** сложность бэкенда

Выдай пользователю уникальный email-адрес, который превращает входящие рассылки в записи ленты.

**Что сделать:**

- Генерация уникального адреса `@your-domain.com` для каждого пользователя
- Приём входящих писем и их преобразование в записи ленты
- Извлечение чистого контента из HTML рассылки (убрать почтовое оформление, трекинговые пиксели, ссылки отписки)
- Показ рассылок рядом с RSS-контентом в одном интерфейсе
- Поддержка распространённых форматов рассылок (Substack, Buttondown, Mailchimp, ConvertKit)
- Верификация email и фильтрация спама

**Чем это впечатляет:** приём почты — по-настоящему сложная бэкенд-инженерия: получение SMTP, разбор MIME, очистка HTML, обработка вложений. Это решает реальную проблему (рассылки и RSS — отдельные миры) и показывает глубину full-stack.

## 4. Аналитика чтения

**Область навыков:** визуализация данных

Отслеживай привычки чтения и показывай содержательные данные о том, как потребляется контент.

**Что сделать:**

- Прочитанные статьи за день/неделю/месяц (линейный или столбчатый график)
- Самые читаемые категории и источники (диаграмма с разбивкой)
- Трекер серии чтения (дни подряд, в которые прочитана хотя бы одна статья)
- Тепловая карта активности, показывающая паттерны чтения (время суток, день недели — как граф контрибуций на GitHub)
- Среднее время между публикацией записи и её прочтением (метрика свежести)
- «Темп чтения» — прочитано записей против получено (успеваешь ли ты?)
- Экспорт данных о чтении в CSV или JSON

**Чем это впечатляет:** визуализация данных — дизайнерский навык с большой отдачей. Убедительная аналитическая панель требует построения графиков, агрегации данных, осмысленного выбора метрик и ясной визуальной подачи. Она превращает читалку в инструмент, осознающий привычки своего владельца.

## 5. Чтение с приоритетом доступности

**Область навыков:** доступность

Выйди за рамки соответствия WCAG и создай по-настоящему инклюзивный опыт чтения.

**Что сделать:**

- Полноценная работа со скринридером: корректные ARIA-ориентиры, подписи и live-регионы
- Режим уменьшенной анимации, который учитывает `prefers-reduced-motion` и убирает все анимации
- Режим высокой контрастности с коэффициентами контраста уровня WCAG AAA
- Настраиваемые размер шрифта, межстрочный интервал и длина строки для комфортного чтения
- Опция шрифта, удобного при дислексии (OpenDyslexic или аналог)
- Стили focus-visible, одновременно функциональные и вписанные в эстетику
- Skip-ссылки и логичная иерархия заголовков во всём приложении
- Индикаторы статуса, безопасные для людей с цветовой слепотой (никогда не полагаться только на цвет)
- Клавиатурная навигация, не показывающая кольцо фокуса пользователям мыши (`:focus-visible`)
- Страница с заявлением о доступности, где описано, что реализовано и протестировано

**Чем это впечатляет:** разработка с приоритетом доступности — принципиальный навык, который говорит о заботе обо всех пользователях. Выход за рамки базового (alt-тексты, контраст) к настройкам чтения, полноценному ARIA и уменьшенной анимации демонстрирует глубокую экспертизу, которую работодатели высоко ценят.
